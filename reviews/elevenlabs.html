ElevenLabs

VerdictKeep — the last tool I'd cut

The voice quality stopped being the weak link in my pipeline about a year ago. Everything downstream of it is still the hard part.

Worth it for
narration, VO beds, and any pipeline where the voice carries the piece
Skip it if
you need a talking head whose mouth matches — that's a lip-sync problem, not a voice problem

What I use it for

Every narration track in my pipeline is ElevenLabs. Script goes in, a voice ID comes back as audio, FFmpeg lays it under the picture. My animated host has a fixed assigned voice ID so the character sounds identical across a whole series — that consistency is the actual product, more than raw realism.

The part nobody mentions: API key scopes

This is the one thing I'd want to read before signing up. ElevenLabs API keys are scoped, and the scopes are not all enabled by default. My key authenticates fine for the endpoint that matters — GET /v1/voices returns 200 and synthesis works — but GET /v1/user returns 401, "missing the permission user_read".

Practical consequence: you cannot read your own remaining credit balance programmatically unless you deliberately grant user_read when you create the key. If you're building anything that should stop before it blows through a quota, grant that scope at creation time. I didn't, and I spent real time assuming my key was broken when it was only narrow.

Where it sits in the stack

Marginal cost per video is effectively zero once you're on a subscription, which changes how you work: I re-record narration freely instead of protecting a take. That's the real unlock of synthetic voice for short-form — not that it's cheap, but that revision is free.

Honest limits

  • It produces audio, not performance. Dense, emotionally-specific reads still sound like a very good machine.
  • Credits disappear faster than you'd expect when you iterate on long scripts.
  • It makes the lip-sync problem worse, in a sense: the audio is now good enough that a mismatched mouth is the only thing a viewer notices.
