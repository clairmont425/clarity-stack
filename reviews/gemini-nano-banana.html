Gemini image generation

VerdictKeep — standardised on it

The reference-image input is the whole reason. Without an anchor, every image is a new person wearing the same description.

Worth it for
generated humans that must look like the same person in every shot
Skip it if
you need one perfect hero image of an object and identity is irrelevant

The one feature that decided it

I generate recurring characters, so the only question that matters is whether the model will accept a canonical face as an image input and stay anchored to it. Gemini's pro image model does. I pass the same canonical_front.png on every single call, and the face and skin hold across shots.

The counterpart model — Imagen 4 Ultra — is, to my eye, the better pure text-to-image photorealist, but it accepts no reference image at all. So the split in my pipeline is mechanical, not aesthetic:

ShotModelWhy
Any face, any skin, any shot where it must be this person Gemini pro image (reference-capable) Canonical image goes in as a reference and anchors identity
Objects only — product, cityscape, food, abstract Imagen 4 Ultra Highest text-to-image realism; no identity to preserve, so the missing reference input costs nothing

At three and a half cents a 1K image, stills are a rounding error next to video — six 5-second Kling clips cost more than sixty images. Generate more stills than you think you need and pick; that's the economically correct behaviour here, and it's the opposite of how video pricing wants you to work.

Honest limits

  • Anchoring reduces drift, it doesn't eliminate it. Pose and lighting changes still pull the face. See character consistency for the strength setting that actually helps.
  • A reference-anchored image is slightly less "wow" than an unconstrained one. That's the trade: consistency costs a little peak quality, and for series work it's worth it every time.
